# Valhalla Combat 全面修复与 SKSE Menu Framework 迁移计划

日期：2026-11-05。源码基线：`364ff1740d0dfbce24bf8d8139c6635408f2e69f`。

本计划覆盖此前三份报告中的全部确定缺陷、条件性安全缺陷和待运行时核验项，并将 MCM 配置菜单替换为 SKSE Menu Framework。实施后的交付、证据及剩余实机验收见 [实施报告](2026-11-05-implementation.md)；下文保留原验收要求。

依据：[运行时与发布审查](2026-11-05-runtime-safety.md)、[处决诊断](2026-11-05-execution-diagnosis.md)、[全功能执行时态审查](2026-11-05-feature-phase-audit.md)。编号 A/B、T/L 沿用这些报告。

## 1. 目标与行为基线

修复目标是消除已发现的未定义行为、失效对象使用、后台引擎修改、共享状态同步缺口、旧任务干扰新状态、效果创建与回收不配对，以及确定的玩法实现错误。不能用增加 sleep、统一加锁或调大眩晕伤害替代这些修复。

默认保留当前已经确认的玩法：普攻眩晕倍率 0、眩晕属性公式、约 3+7 秒恢复、后续普通近战命中触发自动处决、手动处决仅响应按下、现有资格限制和逐命中奖励。新菜单允许调整已经实现的数值，不顺便加入同击处决、输入缓冲、玩家被处决或新的等级限制规则。

“所有问题完成”的判定分两部分：确定缺陷有回归验证；待证项有反汇编或游戏内轨迹给出结论并完成必要修复。待证项不能仅靠代码审阅标记完成；本计划也不将尚未证明的栈破坏写成已发生事实。

兼容方案采用 CommonLibSSE-NG 的 SE/AE 多目标构建，发布同一个 DLL，不为每个游戏版本单独实现或构建。NG 已封装的地址、布局和版本化调用优先直接使用；插件元数据声明本身不会修正自定义 Hook 的偏移、虚表槽或签名。实测按 SE/AE 与已知 ABI 差异边界选代表版本，发布说明区分库支持范围与实际测试范围。参见 [NG 多运行时构建说明](https://github.com/alandtse/CommonLibSSE-NG/blob/v11.0.0/README.md#multiple-runtime-targets) 和 [1.7.99 输入虚表的版本化封装](https://github.com/alandtse/CommonLibSSE-NG/blob/v11.0.0/include/RE/P/PlayerInputHandler.h)。

## 2. 统一运行契约

### 2.1 线程和执行阶段

新增一个轻量 `CombatRuntime`，负责会话、游戏阶段任务和定时工作；具体处决、格挡、眩晕逻辑仍留在各自模块。它不是通用线程池，也不另建后台工作线程。

| 入口 | 允许的工作 | 状态交接 |
| --- | --- | --- |
| 已核实的游戏更新/任务阶段 | 修改 Actor、动画、法术、AV、时间倍率和战斗容器 | 成为战斗可变状态的所有者；记录线程与阶段断言 |
| 输入、动画、原生命中、Precision | 按真实线程契约执行需要即时完成的决策 | 同线程走同步接口；跨线程提交复制后的请求，不把引擎事件对象留到回调之后 |
| 投射物碰撞 | 仅在已核实的 ABI、物理锁和线程约束内执行必要的同步拦截 | 复制身份和判定结果；特效、反射/销毁等在适当阶段执行，不保存 collector/collidable 指针 |
| TrueHUD / 导出 API 查询 | 读取已发布的只读状态快照 | 快照使用互斥保护的复制或不可变共享对象发布；不与可变 stun 对象共享无锁字段 |
| SKSE Menu Framework 渲染 | 编辑菜单草稿、读取状态、提交设置命令 | 不直接调用战斗 handler、修改 Actor/游戏设置或读写可变配置全局量 |

不能预先把所有引擎回调都认定为主线程。W0 先验证入口线程与物理阶段。必须同步返回的碰撞/PreHit 结果不整体延迟，否则会放行本应拦截的命中；必要的决策事务应与可延迟副作用拆开。若入口确实并发，使用短小的纯状态事务或快照交接，不持容器锁调用外部引擎/API。

`ModAPI.cpp` 也纳入边界：保持 V1/V2 虚表和导出兼容；同线程写入保持同步，非所有者线程的写入通过句柄和数值命令转交，查询读取快照，并明确调用时态。`noexcept` 边界不允许配置、分配或容器异常穿出。调用者仍须保证传入对象在本次 API 调用期间有效，不能靠检查非空来验证任意坏地址。

### 2.2 对象、请求和会话

- 延迟请求只保存 ActorHandle / ProjectileHandle、稳定表单身份和复制的数值；消费时解析句柄，把 NiPointer 保留到本次使用结束。长期 stun 数据、攻击缓存不保存裸 Actor 地址。
- 每个请求带 `sessionId` 和对应操作的 `requestId`。读档/新游戏切换会话；重新按键、取消、关闭相关功能只使对应请求失效，不能影响新一轮请求。
- 每个执行者/目标只允许兼容的一个待处决请求；每个格挡按键周期拥有自己的松开请求；EC 和慢时间按实际效果实例登记。
- 暂停、加载中、未完成初始化时不消费战斗任务。任务在执行时复查当前状态，不能仅依赖提交时检查。
- 任何容器迭代器不跨越可重入的引擎调用。先完成状态事务，再解锁/离开容器访问，最后执行副作用。

### 2.3 时钟和清理

| 工作 | 计时规则 |
| --- | --- |
| 精准格挡/冲撞窗口、冷却、眩晕恢复 | 保留当前游戏 dt 语义，暂停冻结 |
| 格挡承诺松开、EC 持续时间、慢时间持续时间、提示闪烁 | 使用暂停期间不推进的真实秒时钟，避免时间倍率改变自身持续时间 |
| 处决播放 | 下一次已验证安全阶段消费，不加入任意 50/100ms 等待，不自动无限重试 |

暂停依据游戏实际暂停状态及框架实际暂停信号；允许游戏继续的菜单不会无条件冻结战斗。无有效玩家更新时不补跑一批已经跨越加载场景的任务。

清理以“本插件曾创建什么”为准，独立于当前是否允许创建新效果。统一处理自然恢复、关闭设置、目标死亡/卸载、会话结束。暂时不能恢复动画的目标保留待清理记录，在可处理时重试；没有清理成功或确认目标终止前，不先删除唯一的所有权记录。每帧工作有界，同一目标不重复堆积任务。

## 3. 工作包与实施顺序

依赖顺序：`W0 → W1 → W2/W3/W4 → W5 → W6 → W7`。W0 的 ABI 取证可持续到 W7，但不能带着未确定的碰撞契约发布。每个工作包单独提交、带对应回归结果；已有功能随迁移逐段接入。

### W0：固定依赖、Hook ABI 与可重现构建

涉及：`src/include/Hooks.h`、`src/bin/Hooks.cpp`、`src/include/offsets.h`、`src/bin/main.cpp`、CMake、依赖版本记录。

1. 固定并记录 CommonLibSSE-NG 的确切提交、编译器和游戏运行时；不使用“当前最新”替代已声明的 v11 契约。
2. 对 Projectile 0xBE、调用者和原函数链反汇编，按已知 ABI/指令布局差异选择代表版本，确认第二参数究竟是 collidable 还是 collector，以及 bool 返回值。取得证据后再调整 Hook/Relocation 的完整函数类型；同步核查自定义 Arrow/Missile 继承槽、PlayerUpdate、ProcessButton 和 callsite 偏移。NG 已封装的版本差异直接使用，不重新手写一套逐版本适配。
3. 逐项记录寄存器参数、返回寄存器、虚表槽、原函数链及调用次数。拦截分支也必须返回真实契约要求的结果；不能把 `void` 简单改成 `bool` 就宣称验证完成。
4. 修复未初始化 cost、loader 计数器、空动作列表、缺失表单/空 process/空 VFX 等可达保护；清查有同样所有权模式的 helper，包括 shooter、bodyPartData、biped 和节点访问，按实际契约处理。
5. 缺配置目录、坏 INI 数字、越界/非有限数值给出明确错误与默认策略；数据与表单完成后才开放战斗入口。初始化失败不能留下“部分功能已装钩且状态未就绪”的工作状态。
6. 构建 Valhalla 时允许 `COPY_OUTPUT=OFF` 且不要求游戏部署目录；增加可独立运行的回归目标。保留现有严格警告，补充遮蔽、未初始化和函数类型检查；静态分析聚焦自有代码。

**验收：** SE/AE 多目标的同一个 DLL 干净 Release 构建通过，静态检查没有本次相关问题；自定义 Hook 有契约记录，关键地址缺失或契约不匹配时明确拒绝不安全安装。不额外建立“每个版本单独放行”的精确版本白名单；NG/Address Library 覆盖的兼容范围与实际测试范围分别说明，没有目标二进制的测试项标记未实测。

### W1：调度、加载边界和所有权基础

涉及：新增 `src/include/CombatRuntime.h`、`src/bin/CombatRuntime.cpp`，`main.cpp`、`ValhallaCombat.hpp`，各 handler 的 reset/cleanup 入口。

1. 实现最小接口：提交游戏阶段请求、登记/取消定时操作、推进时钟、切换会话、发布查询快照。队列只在转交时加锁，消费后不持队列锁调用引擎。
2. 消除活动路径中的 detached thread / jthread / sleep；处决、松开格挡、EC、慢时间、两个提示闪烁均迁入受控调度。
3. 明确 `Loading → Ready → Active` 状态。PreLoadGame 使旧请求失效；PostLoadGame/NewGame 完成状态重建后才接收新战斗请求；加载失败不恢复旧请求，退出到主菜单也结束战斗会话。钩子和输入在未就绪期间只走安全原路径。
4. 清理攻击缓存、按键/格挡/冲撞计时、待处决、提示、stun/debuff 记录及本插件效果所有权。访问旧场景前必须确认当前阶段允许，不能在加载中遍历并操作已经卸载的 Actor。
5. 对可能被存档保留的自加 perk、EC 法术和倒地状态建立最小所有权账目。以 SKSE 序列化保存需要恢复清理的 FormID/效果类型，读取时经 FormID 解析重建当前句柄；不序列化旧裸指针、旧任务或墙钟期限。验证哪些状态实际被存档保留，避免在读档时盲清第三方相同状态。

**验收：** 排队后立即读档/新游戏/退主菜单，旧请求执行次数为 0；连续加载不累积状态；暂停时效果期限冻结；插件创建的持久副作用能在加载后正确对账。所有引擎修改都能追溯到允许的执行阶段。

### W2：格挡、攻击与投射物

涉及：`blockHandler.cpp/.h`、`Hooks.cpp/.h`、`attackHandler.cpp/.h`、`animEventHandler.cpp`、`Utils.h`。

1. 箭矢消耗使用一个初始化后的变量。物理格挡不足按 `未覆盖比例 = 1 - clamp(可用耐力 / 所需耐力, 0, 1)` 换算生命伤害；所需耐力为 0 时单独处理。保证输出有限、非负且不超过本次对应伤害。
2. 所有扣耐力路径完成后执行一致的耗尽判定，覆盖刚好为 0、timed block 以及不足的情况；不依赖之后碰巧出现的动画事件补清状态。
3. 先维护真实按下/松开状态，再决定是否重复开窗。普通键、替代键和功能关闭都能释放已存在的 held 状态；按键绑定改变时取消旧绑定留下的状态。
4. 延迟松开只携带按键周期和到期信息；消费时取得当前 PlayerControls/handler，以已验证方式构造和销毁合成事件。删除长期保存的 handler/data/event 指针，完整保护玩家访问；旧周期不能发送 blockStop。
5. Precision 的 timed block 与 tackle 各自门控。跨入口碰撞去重先取实际调用证据；必要时使用真实攻击/弹体接触身份做一次性结算，不以固定毫秒窗口吞掉合法连击。
6. 投射物扫描失败继续检查后续接触，只有成功消费才提前返回；一个回调最多成功结算一次。判定与延期弹体修改共享请求身份，避免同一接触重复扣费/退款。
7. 在 ABI/物理契约验证后的安全阶段重新取得当前碰撞对象，连同 owner/cause 一起更新过滤状态；不传旧 collector 指针，也不永久用 nullptr 跳过 filter。验证反射回原射手、近距离和连续反射。
8. 攻击缓存使用句柄和实际攻击周期；先取出/删除缓存，再结算 miss。由现场 preHitFrame/hit/attackStop 轨迹决定周期归属与迟到命中处理，保持当前逐命中奖励规则，不臆造每挥击奖励上限。

**验收：** down-up-down 后 held 为真且旧松开无效；关闭开关/改键不残留 held；倍率 0.5、1、2 的格挡伤害符合比例；恰好扣空立即耗尽；Precision 独立 tackle 生效；无效首接触不遮挡玩家；攻击缓存不跨场景、不跨引擎调用保留迭代器。

### W3：眩晕、耗尽、反应与附加效果

涉及：`stunHandler.cpp/.h`、`debuffHandler.cpp/.h`、`reactionHandler.cpp`、`Utils.h`、`TrueHUDUtils.h`、EC 实现。

1. stun 数据保存句柄；无效解析不创建数据。查找/插入返回唯一已登记对象，所有数值修改遵循同一所有者线程或完整事务，不再在共享锁下修改 pointee。TrueHUD getters 读快照，broken 集合复制也遵循同步协议。
2. 统一 debuff 的 enter/exit：自然恢复、显式停止和功能关闭均清理 graph、自己添加的 perk、提示与记录。清理不以当前 bUIAlert 或记录是否仍存在作为唯一前提。
3. stun/debuff 闪烁改为调度器的周期操作，取消不依赖显示开关。句柄失效、目标终止、加载切换均回收，杜绝 bool 标志的启动竞态和 ABA。
4. 记录实际施加的倒地状态；关闭开关仍执行恢复。恢复因 3D/killmove 等暂不可达时保留待清理身份，不先删除记录；不解除其他来源的倒地。
5. 种族查询统一使用 find，不隐式写入 Humanoid；未知种族保持明确的未映射结果。VFX 失败只跳过该次效果，不中断整个命中结算。
6. EC 记录是否由本次操作成功加入法术；已存在的法术保持原规则，不擅自取得删除所有权。到期在游戏阶段解析句柄并核对代次后移除；取消/加载清理只处理自己拥有的效果。
7. 慢时间由一个管理器聚合活动请求：有效倍率取这些请求中最慢者；任一较短请求结束不能取消较长请求。第一份请求保存原倍率，最后一份结束恢复它；发现其他来源修改了本插件最后写入值时停止本次所有权并保留外部值，不硬写 1。会话结束有独立安全恢复流程。
8. `counterAttack` 使用实际反击来源及 fStunCounterAttackMult；普通 powerAttack 路径保持原倍率。覆盖内部调用和导出 API，不把无消费者的字段继续显示为已生效。

**验收：** 满耐力后 graph/perk/记录均清理；UI 关闭不能保留 worker；倒地后关开关仍恢复，卸载后重新加载能补清理；慢时间重叠与原倍率 0.4 的用例通过；EC 删除只发生于允许线程和对应实例；共享读取不会访问可变裸对象。

### W4：处决完整链路

涉及：`executionHandler.cpp/.h`、`hitProcessor.cpp`、`data.cpp/.h`、`inputEventHandler.cpp`、播放接口。

1. 无效候选只跳过。先判定种族、武器、资格和可用动作，再从可用候选中按距离排序；最近不合格者不能阻挡后续有效者。
2. 所有分支返回实际结果：拒绝原因、已排队、引擎接受/拒绝。缺动作/徒手无分支/空列表不能返回成功。使用可用动作筛选，未知 mod 种族不能只按外形强行映射。
3. 动作选择统一在状态所有者线程完成，消除共享 RNG 竞争；不为一次随机选择创建线程。
4. 用执行者/目标句柄和会话提交请求。消费前重新验证双方存活、3D、process、killmove、骑乘、资格、当前破防、动作表单，以及手动搜索适用的距离；解析引用保留到播放结束。
5. 引擎播放 bool 结果进入状态和日志，释放 pending 标记。仅提交不算播放成功；失败不会永久占用角色，也不无条件多次尝试同一 idle。
6. 保留自动处决与伤害处理的现有规则。补充队列期间致死、恢复满眩晕、另一处决先开始的取消用例，避免为了“当击成功”私自吞掉正常伤害。

**验收：** selection/dispatch/timing 三类现有诊断失败转为针对正确行为的通过；徒手无动作明确拒绝；排队后目标死亡/卸载、执行者 process 消失时不调用播放；连续按键只保留一个合法请求；实际引擎拒绝能在菜单诊断中看见原因。

### W5：统一设置与旧配置迁移

涉及：`settings.cpp/.h`，新增 `SettingsStore`，菜单数据模型、运行时设置提交、原 ModCallback 入口。

1. 用一个有类型的设置定义表描述名称、默认、范围、序列化与说明。`bBlockedHitRegenStamina` 改为 bool；新默认以已发布设置文件的有效默认为基准，使旧安装和干净安装遵循同一规则。保存配置 schema 版本。
2. 新权威路径：`Data/SKSE/Plugins/ValhallaCombat/Settings.ini`。文件不存在或没有新 schema 标记时一次性迁移，优先级为：统一内置默认 → 旧包内 MCM defaults（如存在）→ 原旧版 SKSE 文件（如存在）→ MCM 用户覆盖。该 SKSE 路径与历史路径相同，必须以 schema 区分，不能只以文件存在判定已经迁移。带当前 schema 的文件不再自动接受旧 MCM 覆盖；未知未来 schema 不自动降级改写。
3. 写入使用同目录临时文件与原子替换；同路径旧文件先保存迁移备份，其他旧文件保留，迁移记录源路径、有效键和忽略原因。写入失败保持原生效配置，菜单保留草稿并显示错误；不能提示已应用成功。
4. 菜单采用“编辑草稿 → 校验 → 串行提交/持久化 → 游戏阶段应用新值并清理旧状态 → 发布结果”的单一流程。设置应用有版本号和结果回执，避免旧 Apply 覆盖新值。控制命令在已验证的游戏任务阶段处理，不随战斗时钟一起冻结，确保暂停菜单内 Apply 可得到回执；加载中或暂不允许的动画清理明确显示待处理，在世界就绪后完成。分别显示已保存版本、生效版本和待清理状态，不将文件写成功等同于全部引擎副作用完成。渲染回调不直接持久化或操作引擎。
5. 热切换对已经存在的状态执行退出：耗尽/倒地、按键与改键、提示、慢时间、EC、stun/HUD 控制。哪些开关控制哪些已生效状态写成设置差异表，不全局粗暴 reset 所有战斗状态。
6. 完美格挡界面改为当前真实使用的累计次数 uPerfectBlockAccum；旧 fPerfectBlockWindow 不进行“秒→次数”的伪转换，迁移时记录其未生效并说明替代控件。
7. bExecutionLimit、bPlayerExecution 及未接入的 spirit/balance/AI 项不继续伪装成有效功能。迁移保留原文件并说明这些字段未被支持；新菜单不提供虚假可用开关。本轮不凭注释发明等级阈值、玩家处决和动作支持。
8. 移除 dmenu_updateSettings/MCM Helper 更新依赖；TrueHUD/Precision 状态直接来自真实 API 结果。ESP 中菜单状态 globals 与其他脚本的引用先核查，再决定保留兼容数据还是删除菜单专用引用。

**验收：** 无 MCM/SkyUI 的干净配置路径可工作；缺键、坏数字、只保存单个旧键、旧完美窗口、同路径无 schema 旧文件、已有新文件、未来 schema 和保存失败均有确定结果。菜单内暂停应用可收到回执；待处理状态可见，完成后显示值、落盘值和 gameplay 生效值一致；重启后保留设置。

### W6：接入 SKSE Menu Framework，替代 MCM

框架来源：`E:/source/repos/SKSE-Menu-Framework-3-master`，使用其 `resources/SKSEMenuFramework.h` 公共消费端 SDK。当前本地源码导出 Framework 3.8 / API 1；记录实际采用的头文件哈希与许可。仅在 Valhalla 工程接入，不修改或构建框架本体。

涉及：新增 `src/include/Menu.h`、`src/bin/Menu.cpp`、固定版本 SDK 目录，`main.cpp`、CMake、菜单资源、打包文档。

1. 在 PostPostLoad 注册，预检已加载 DLL 及所需导出/API 版本。`IsInstalled()` 仅检查磁盘文件，不作为就绪依据；首次调用具有静态缓存的 wrapper 前确认导出存在，避免永久缓存 null。
2. 通过 AddSectionItem / AddWindow 注册 `Valhalla Combat` 页面；回调使用 SDK 的 `__stdcall` 类型。消费框架现有 ImGui 上下文和封装，不引入第二个 ImGui 实例，不安装自有渲染 Hook。回调与注册对象保持插件存续期有效。
3. 页面分为“总览、耐力、格挡与冲撞、眩晕与处决、效果与兼容、诊断”。全部有效旧设置有对应控件和单位；完美格挡显示累计机制，未知或未实现功能不冒充已生效。
4. 提供应用、撤销草稿、恢复默认、重新读取文件。恢复默认只改草稿，应用后才生效；总览显示菜单框架、TrueHUD、Precision、动作数据加载与设置版本的实际状态。
5. 按键重绑定支持现有键码、鼠标/手柄编码和解除绑定；在框架输入回调的有效期内读取事件并复制结果。绑定采集期间消费输入，避免同一次按键又触发处决/格挡；冲突提示和修改旧 held 状态一并处理。
6. 中文文本走框架字体/翻译能力并实测字体可用性；正确处理暂停、非暂停菜单、键鼠/手柄导航。诊断页只读快照，不在渲染线程扫描 Actor 或修改战斗状态。
7. 框架缺失/版本不支持时明确报告菜单不可用，仍可读取文件配置安全运行战斗；不回退到 MCM。发布依赖明确要求安装经验证版本的 SKSE Menu Framework。
8. 资产包移除 MCM JSON/默认文件和菜单专用 PEX/ESP 脚本入口；旧配置仅作为迁移输入。先核对 ESP masters、脚本属性和非菜单用途，保留必需玩法表单、音效、动作、种族映射等资源。更新安装/升级说明，清楚列出需移除的旧菜单文件。

**验收：** 游戏中可从框架打开新菜单，保存、重开、改键、暂停/非暂停均正常；关闭框架菜单后无输入残留。没有 MCM Helper 或菜单专用脚本仍能完整配置所有活动功能。框架缺失/加载顺序变化不会空函数调用崩溃。
